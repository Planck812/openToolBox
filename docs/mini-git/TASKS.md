## 1. 拆分约定

### 1.1 粒度

- **单个任务不超过 2 小时**。超出的一律继续拆分。
- 工时为**净编码与自测时间**，不含评审、等待与会议。
- 每个任务都有明确的完成判据，判据必须可被他人独立核验。

### 1.2 编号

`<模块号>-<序号>`。模块号见第 2 章。编号只增不改；任务取消时保留编号并标注，不回收。

### 1.3 依赖标记

| 标记 | 含义 |
| --- | --- |
| 空 | 无前置依赖，可立即开工 |
| `A-1` | 必须在 A-1 完成后开工 |
| `~A-1` | 软依赖，可并行开工但合并前需 A-1 就位 |

### 1.4 任务类型

| 标记 | 含义 |
| --- | --- |
| 🔧 | 基础设施 / 工具链 |
| ⚙ | 后端实现 |
| 🖥 | 前端实现 |
| 🧪 | 测试实现 |
| 📐 | 实测验证类（结论会影响后续设计参数） |

### 2.1 并行度建议

```
第 1 波（无前置，可同时开工）
  M0 基础设施   M1 常驻窗口   （2 人并行）

第 2 波
  M2 后端读取   M3 协议安全   M4 前端基座   （3 人并行）

第 3 波
  M5 首屏   M6 布局   （2 人并行，M6 完成后解锁第 4 波）

第 4 波（并行度最高）
  M7 文件树   M8 文件查看   M9 Git 面板   （3 人并行）

第 5 波
  M10 差异视图   M12 通用能力   （2 人并行）

第 6 波
  M11 刷新与会话

第 7 波
  M13 测试实现（贯穿全程，此处收尾）   M14 性能与验收
```
