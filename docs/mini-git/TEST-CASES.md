## 1. 测试策略

### 1.1 测试分层

| 缩写 | 层级 | 承载位置 | 适用范围 |
| --- | --- | --- | --- |
| RU | Rust 单元测试 | `src-tauri/src/**` 的 `#[cfg(test)]` | 纯函数逻辑：编码判定、二进制判定、路径规范化、时间解析、差异结构构造 |
| RI | Rust 集成测试 | `src-tauri/tests/` | 「给定仓库状态 → 期望结构化输出」，使用仓库夹具 |
| FU | 前端单元测试 | `src/**/__tests__/*.test.ts`（vitest + jsdom） | 纯函数：模糊匹配打分、自然排序、时间格式化、Markdown 净化、差异行配对与行内高亮 |
| CT | 组件测试 | `tests/*.spec.ts`（vitest） | 组件渲染、交互、状态流转、空态与错误态 |
| E2E-A | 桌面端到端（现框架可跑） | `tests/desktop/specs/`（webdriverio + tauri-driver） | 单窗口、纯 webview 内交互 |
| E2E-B | 桌面端到端（需扩展框架） | 同上，依赖基础设施 I-2 ~ I-7 | 应用重启与状态恢复、多窗口切换、窗口尺寸、剪贴板、埋点日志采集、帧时间采样 |
| E2E-M | 人工用例 | 手工回归清单（第 11.2 节） | 框架无法触达：macOS 全部 E2E、托盘菜单、系统目录选择器、多显示器拔插、输入法组合、真实抓包、冷态性能 |
| CI | 构建期静态检查 | `.github/workflows/test.yml` 的 `audit` job | 依赖与 feature 断言、禁用 API 扫描、配置断言、i18n 一致性 |

> **现状提示**：仓库当前仅有 `build.yml`（仅在 tag 上构建），**不存在执行测试的 workflow**；`tests/desktop/` 的编排是单会话、单窗口、Windows 专用。E2E-B 与 CI 两层在基础设施落地前不可执行，依赖项见第 11.1 节。
>
> **macOS 限制**：`tauri-driver` 无 WKWebView 的 WebDriver 实现，macOS 下的桌面自动化无解，全部归入 E2E-M。

### 1.2 分层落点原则

1. **能下沉就下沉**。后端 Git 能力以纯函数形式暴露（输入仓库路径与参数 → 结构化输出），使绝大多数逻辑可在 RU / RI 层覆盖，不压到 E2E。
2. **前端纯逻辑必须可独立测试**。模糊匹配打分、自然排序、时间格式化、编码与二进制判定的前端侧、Markdown 净化、差异行配对与行内高亮——这七项要求实现为不依赖组件的纯函数，用 FU 表驱动测试。
3. **标 FU 的用例其步骤必须是「调用函数」而非「打开界面」**。涉及渲染或存储的一律标 CT / RI / E2E。
4. **E2E 只覆盖其他层做不到的**：窗口生命周期、跨进程状态恢复、只读挂载、系统交互（目录选择器、全局快捷键、文件管理器）、截图与取色类验证。
5. **跨平台差异用 CI matrix 覆盖**，不在单一平台上模拟。

### 1.3 预期结果的书写要求

预期结果必须可被程序或人工明确判定。以下措辞禁止出现在预期列：「正常」「正确」「均成功」「无异常」「合理」。涉及「不暴露底层错误」这类抽象要求，须转写为可断言形式（如：提示文本不含 `Error`、`panic`、`0x`、文件系统绝对路径、Rust crate 名）。

预期结果中不得包含条件分支（「能打开则……失败则……」），此类写法使用例必然通过。应按平台或配置拆分为多条确定性用例。

### 1.4 缺陷分级

| 等级 | 定义 | 放行门限 |
| --- | --- | --- |
| S1 | 崩溃、宿主进程被连带终止、数据展示错误（差异或历史内容与 Git 实际不符）、只读约束被破坏、非预期网络请求 | 归零 |
| S2 | 核心场景（场景一）阻塞，或 P0 需求功能缺失 | 归零 |
| S3 | P1 需求功能缺失、明显的交互缺陷、性能指标未达标 | ≤ 5 个 |
| S4 | P2 需求缺失、文案问题、轻微视觉偏差 | 不阻塞放行 |

## 2. 测试环境与夹具

### 2.1 基准仓库

按 PRD 7.1.2 生成三档基准仓库，要求提供可重复执行的生成脚本（置于 `src-tauri/tests/fixtures/`），保证跨机器结果可比。

| 档位 | 提交数 | 分支 | 标签 | 已跟踪文件 | 最深层级 | 单目录最大条目 | 体积 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 小（S） | 500 | 5 | 5 | 500 | 6 | 100 | < 20 MB |
| 中（M） | 10 000 | 30 | 50 | 5 000 | 10 | 1 000 | < 300 MB |
| 大（L） | 100 000 | 200 | 500 | 20 000 | 12 | 5 000 | < 2 GB |

生成脚本必须保证：

| # | 约束 | 说明 |
| --- | --- | --- |
| 1 | 使用 `git fast-import` 生成，不用循环 `git commit` | 10 万次进程启动在 Windows 上需数小时；fast-import 直接写 packfile，约 10~30 分钟 |
| 2 | `gc.auto=0`、`gc.writeCommitGraph=false`、`fetch.writeCommitGraph=false`、`maintenance.auto=false` | 仅写「不产生 commit-graph」不足以保证——auto-gc 在 10 万提交规模上几乎必然触发并写入 commit-graph |
| 3 | `core.fsmonitor=false`，index 版本固定 | 保证跨机器一致 |
| 4 | 提交时间可控（可注入固定的作者时间与提交时间） | TC-5D.3、TC-5D.4、TC-B.B13 依赖 |
| 5 | 可指定 `core.autocrlf` | TC-6.25 依赖 |
| 6 | **确定性自检**：脚本结束时断言 `HEAD` 等于记录在案的固定 SHA | 「跨机器可比」的唯一保证；TC-5D.4 的哈希字典序期望值直接依赖具体 SHA |
| 7 | 夹具目录纳入 `.gitignore`，路径不含空格 | 避免与 FX-PATHS 的测试意图混淆 |

**补充档位**：TC-N.1.5 需要「2 万已跟踪文件」（复用大档），TC-N.1.6 需要「8 万未忽略文件」，后者三档表中无对应来源，需单独生成 **FX-MANYFILES**。

**大档仓库不进入 CI**。其在专用基准机上常驻（见第 11.1 节 I-13），不经 CI 缓存或制品传输——GitHub Actions 的 artifact 不能跨 workflow run 直接取用且计入配额，而 `actions/cache` 的 10 GB 总额已被现有的 Rust 缓存占用大半，再塞 2 GB 夹具会将其挤爆。CI 中改用 **L-lite**（2 万提交 / 3000 文件 / < 300 MB）配合不变量断言（TC-5D.5、TC-5D.7）替代。

### 2.2 专用夹具仓库

| 夹具 ID | 内容 |
| --- | --- |
| FX-EMPTY | 已 init、零提交 |
| FX-ONE | 仅 1 次提交 |
| FX-BARE | 裸仓库 |
| FX-WORKTREE | linked worktree（`.git` 为文件）。**不可重定位**：`.git` 文件与主仓库 `worktrees/<name>/gitdir` 均为绝对路径，一经拷贝或缓存还原到不同路径即失效且报错隐晦。必须每次就地生成，禁止纳入缓存 |
| FX-SHALLOW | 浅克隆（存在 `.git/shallow`） |
| FX-SUBMODULE | 含 1 个子模块。两个必踩点：① Git ≥ 2.38 默认 `protocol.file.allow=user`，本地路径初始化子模块会被直接拒绝，须带 `-c protocol.file.allow=always`；② `.gitmodules` 中的本地 URL 为绝对路径，同 FX-WORKTREE 不可重定位 |
| FX-MERGING | 处于合并中间态且有冲突文件 |
| FX-REBASING | 处于变基中间态、游离 HEAD |
| FX-CORRUPT | object 缺失、refs 内容非法。**损坏必须施加在 loose object 上，不得损坏 packfile**——后者会让整个仓库不可读，就测不出「受影响区域降级、其余区域保持可用」这个设计意图（TC-B.A9 / NFR-5.2） |
| FX-ENCODING | 提交信息含 GBK `encoding` header、空提交信息、缺失作者信息。**「缺失作者信息」需 plumbing**：`git commit` 不可能产出作者行残缺的提交对象，须手工拼装 commit 对象字节流后 `git hash-object -t commit -w --stdin` 再 `update-ref`。设空 `user.name` 只会得到 `<>`，不是真正的格式异常 |
| FX-TIME | 含未来时间、1970 年、异常时区（+1400）、时钟回拨的提交 |
| FX-OCTOPUS | 章鱼合并（3 父）、多根仓库、根提交为合并提交、空提交 |
| FX-REFS | 同名分支与标签、含斜杠 / 非 ASCII / emoji / 超长分支名、附注与轻量标签、500 分支 + 1000 标签 |
| FX-PATHS | 文件名含空格 / `#` / `%` / `&` / 引号、非 ASCII、NFD 与 NFC 同名、深层嵌套、空目录 |
| FX-SYMLINK | 符号链接：普通、指向仓库外、循环。**须显式 `-c core.symlinks=true`**——Git for Windows 默认 `core.symlinks=false`，检出时会把链接变成内容为目标路径的普通文本文件，届时测的根本不是符号链接。脚本开头检测权限（需开发者模式或管理员），不满足则显式 skip，不得静默生成错误夹具 |
| FX-CASE | 大小写仅差异的同名文件。**仅做 tree 层验证**——在大小写不敏感的文件系统上两者无法同时检出，工作区会永久处于脏状态并污染所有复用它的用例 |
| FX-LONGPATH | Windows 超长路径（> 260 字符）。需 `core.longpaths=true` 检出；**生成后常规工具删不掉**，清理须用 `robocopy <空目录> <目标> /MIR` 或 `\\?\` 前缀，并置于 CI 的 always 清理步骤中 |
| FX-MANYFILES | 8 万个未忽略文件的工作区（供 TC-N.1.6 使用） |
| FX-CONTENT | 零字节、阈值边界（2 MiB−1B / 2 MiB / 2 MiB+1B）、二进制、UTF-16、无 BOM UTF-8、GBK、含 BOM UTF-8、无末尾换行、混合行尾、单行 1 MB、LFS 指针、损坏图片 |
| FX-RENAME | 相似度 40% / 60% / 90% 的重命名对、跨目录重命名、超过 1000 文件的大规模重命名。**必须自检**：Git 的相似度按 diffcore-rename 的行级 delta 计算，不等于构造时的字节改动比例——朴素构造的「60% 相似」实测可能是 48% 或 71%，正好横跨 50% 阈值导致用例 flaky。脚本末尾须跑 `git diff -M50% --name-status` 断言 60% 那对输出 R、40% 那对输出 D+A，并断言大规模重命名确因超过 `diff.renameLimit` 而未检测 |
| FX-IGNORE | 嵌套 `.gitignore`、`.git/info/exclude`、否定规则、已跟踪但命中忽略规则的文件、含 `node_modules`（2 万文件） |
| FX-DIFF3 | 差异三档模型的边界样本：19 999 / 20 000 / 20 001 行；2 MiB±1B；199 999 / 200 001 行；20 MiB±1B |
| FX-DIRTY12 | 场景一专用：12 个变更文件（4 修改含 2 个不足一屏、3 新增、2 删除、3 未跟踪） |

### 2.3 Git 真值基准

部分用例需要把 Mini-Git 的输出与 Git 的真实结果逐行比对。真值由 Git 命令行在**夹具准备阶段**生成并固化为期望文件，运行时不依赖 Git 命令行，不违反 NFR-4.2。

**对齐口径**（缺任一项都会造成大面积假阳性）：

| 项目 | 设置 |
| --- | --- |
| diff 算法 | `-c diff.algorithm=myers`。libgit2 默认亦为 myers；若一侧用 patience/histogram，同一改动会产出不同但都正确的 hunk 划分 |
| 换行 | git 侧用 `--ignore-cr-at-eol` 与 FR-6.9 的「折 CRLF」对齐 |
| 重命名 | `-c diff.renameLimit=1000`，阈值 50%，关闭复制检测 |
| 前缀 | `-c diff.noprefix=true` |

**排除三类内容**：词级/行内高亮（FR-6.16 为 Mini-Git 自有语义，git 的 `--word-diff` 算法不同）、折叠与上下文行数（FR-6.4 为展示层）、以及任何依赖展示样式的断言。

**真值必须在夹具生成阶段固化为文件**，随夹具一起产出，运行时禁止 shell out 到 git——否则测试会依赖环境中的 git 版本，rename 检测与 diff 输出的版本漂移将导致长期 flaky。固化后，git 版本变化会在「重新生成夹具」时以真值文件 diff 的形式显式暴露。

真值采用三种粒度：`--name-status`（变更分类）、`--numstat`（增删行数）、`--no-color -U3` 的 unified patch 正文（其中的 `\ No newline at end of file` 标记正是 TC-6.26 的验证点，不得过滤）。

### 2.4 只读挂载方法

| 平台 | 方法 | 说明 |
| --- | --- | --- |
| Windows（首选） | VHD 卷级只读挂载 | `New-VHD` → 格式化 → **以读写挂载并在挂载点上原地生成夹具** → 卸载 → `Mount-DiskImage -Access ReadOnly`。覆盖 DELETE、ACL 篡改、内存映射写入等全部路径，卸载即完全还原，无 ACL 残留 |
| Windows（降级） | `icacls <repo> /deny "$env:USERNAME":(OI)(CI)(W,D) /T` | 必须是 `(W,D)`——简单权限 `W` 对应 `FILE_GENERIC_WRITE`，**不含 DELETE**，挡不住删除 `.git` 下的文件，而这正是最该拦截的一类。回滚 `icacls <repo> /remove:d "$env:USERNAME" /T /C /Q`，须置于 always 步骤，否则残留的 deny ACE 会让整个工作区清理失败 |
| Linux | `mount -o ro,bind` | 比 `chmod -R a-w` 彻底：后者对 root 无效，且能否删除目录项取决于父目录权限 |
| macOS | 只读 DMG | 同上理由 |

**三条执行约束**：

1. **只读挂载后无法再制造工作区改动**。脏工作区（FX-DIRTY12）与仓库中间态（FX-MERGING / FX-REBASING）必须在设为只读**之前**构造完毕。
2. **夹具必须在目标卷上原地生成，不得外部生成后拷入**。FX-WORKTREE 的 `.git` 文件、主仓库的 `worktrees/<name>/gitdir`、FX-SUBMODULE 的 `.gitmodules` URL 全是绝对路径，拷入后盘符变化即失效。
3. **应用配置目录不得落在只读卷上**，否则会把「配置写入失败」误判为只读约束被破坏——那是 TC-B.D2 的场景，不是只读验证的场景。

### 2.5 性能数据采集

全部性能用例的数据来源为 FR-9.7 定义的埋点日志，不采用录屏估读。测量条件见 PRD 7.1.1。

埋点格式须在实现前定死为单行 JSON，例如 `{"evt":"perf","stage":"repo_open_first_paint","repo":"M","ms":412,"seq":3}`。日志目录须可由环境变量指定，使测试可在运行前清空、运行后解析，避免并发或重跑时日志串扰。

性能用例按采样成本分两组：

| 组别 | 用例 | 采样方式 |
| --- | --- | --- |
| 热态 | 翻页、目录展开、差异计算、搜索、滚动帧率 | 同一会话内循环 5 次取中位数，成本低，可自动化 |
| 冷态 | TC-N.1.2（宿主冷启动）、TC-N.1.17（冷启动含自动进入仓库） | 每次需重启系统或清空文件缓存。**归入 E2E-M，在专用基准机上半自动执行，不进任何自动化门禁** |

**全部性能用例只在专用基准机上执行**。PRD 7.1.1 要求 4 核 8 线程、16 GB、NVMe SSD 且实时防护保持开启；托管 CI runner 为 2~4 核共享 vCPU，且现有构建流程已将防护排除项加入，其数据不满足测量规范，不作为验收依据。CI 中只做「不崩溃 + 埋点格式正确」的冒烟，不设阈值门禁——否则阈值要么被放宽到失去意义，要么让 PR 长期被性能抖动卡住。

## 4. 功能测试用例

### 4.1 仓库管理（TC-1）

| I-9 | **只读挂载编排**（Windows VHD 只读挂载优先、原地生成；ACL 方案降级；含 always 回滚） | TC-N.3.1、TC-N.3.2 | 详见 2.4 节 |
| I-10 | **快照比对工具**（文件集合相等 + 大小 + SHA-256，显式排除访问时间） | 快照比对用例 | 约 100 行脚本，成本低价值高 |
| I-11 | **网络拦截**（窗口初始化时将 `fetch` / `XHR` / `WebSocket` / `EventSource` 替换为抛错版本） | TC-N.3.6b、TC-10.11 | 比抓包与产物扫描都更严格稳定，作为首选方案 |
| I-12 | **Linux E2E 支持**（去除 Windows 硬编码，接入 WebKitWebDriver + xvfb） | TC-N.4.1b 及 Linux 专属用例 | 工作量中等。**macOS 无此选项** |
| I-13 | **专用基准机**（性能测量与大档夹具常驻，同一台机器） | AC-4a / AC-4b 全部 | 托管 runner 的数据不满足 PRD 7.1.1 的测量规范，本就不能作为验收依据；同时大档夹具在此常驻可免去 CI 传输。属必需品而非优化项 |
