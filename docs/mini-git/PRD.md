## 1. 背景

AI 编码助手普及后，开发者的日常工作重心从「编写代码」转移到「审阅代码变更」。一次典型的 AI 协作流程中，开发者需要在提交前确认改动范围是否符合预期，在提交后回溯某次变更的具体内容。

完成上述审阅只需要三项能力：浏览项目文件结构、查看文件内容、查看 Git 提交历史与差异。但目前这三项能力通常只能通过启动完整的集成开发环境（IDE）获得。IDE 承载的编译、调试、重构、代码补全等能力在纯审阅场景下完全闲置，却带来了可观的启动时间与内存占用成本。

Open-Toolbox 作为轻量桌面效率工具箱，具备接纳该场景的条件：已有的多窗口能力、本地优先的数据策略、统一的主题与国际化体系，都可直接复用。

## 2. 产品目标

### 2.1 目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 提供轻量的本地 Git 仓库审阅能力，完整覆盖「文件树 + 文件查看 + 提交历史」三项高频审阅功能 | 用户可在不启动 IDE 的前提下完成一次完整的提交前审阅（对应 AC-2） |
| G2 | 支持多仓库登记与快速切换 | 从工作台切换到另一个已登记仓库的操作步数 ≤ 3（对应 AC-9） |
| G3 | 常驻运行，随时唤起且工作状态不丢失 | 从隐藏态唤起时界面状态完全不变；宿主进程重启后当前仓库、打开的标签页、文件树展开状态得到恢复（对应 AC-3） |
| G4 | 全程离线、严格只读，不改变仓库任何状态 | 仓库目录设为只读后全部 P0 功能仍可正常运行（对应 AC-8.1） |
| G5 | 端到端效率显著优于启动 IDE | 从唤起到看见第一个变更文件的差异内容，隐藏态 ≤ 1 秒、冷启动 ≤ 3 秒，操作 ≤ 3 次（对应 AC-10） |

### 2.2 非目标

#### 2.2.1 永久非目标

以下能力不在本模块的产品定位内，不做部分实现，也不做入口预留：

| 编号 | 非目标 | 说明 |
| --- | --- | --- |
| EX-1 | 代码编辑 | 不提供文件内容的修改与保存能力。提供交由外部程序处理的出口（FR-4.11），但自身不承担编辑职责 |
| EX-2 | Git 写操作 | 不提供暂存、提交、推送、拉取、切换分支、合并、变基、储藏、还原等任何修改仓库状态的操作 |
| EX-3 | 远程托管平台集成 | 不对接 GitHub / GitLab 等平台的 Pull Request、Issue、CI 状态 |
| EX-4 | 代码智能 | 不提供定义跳转、符号搜索、引用查找、代码补全、静态分析、编译与运行 |
| EX-5 | 协作能力 | 不提供代码评论、审阅流转、多人协同 |
| EX-6 | 终端集成 | 不内嵌终端，不代理执行任何命令行操作 |
| EX-7 | 非 Git 目录浏览 | 不作为通用文件管理器，仅接受有效的 Git 仓库 |

以下为技术方案上的明确排除，需要负向验证（确认功能不存在）：

| 编号 | 排除项 | 说明 |
| --- | --- | --- |

以下能力不在首版范围内，但不是永久非目标，演进方向见 9.3：单文件提交历史、逐行追溯（blame）、仓库全文搜索、任意两版本对比。

### 2.3 产品定位

Mini-Git 是一个**只读的 Git 仓库审阅器**，不是 Git 客户端，也不是代码编辑器。它替代的是 IDE 中被用于审阅的那一部分界面，而非 IDE 本身。

## 3. 目标用户

**主要用户**：使用 AI 编码助手进行日常开发的个人开发者。

**用户特征**：

- 代码主要由 AI 生成或修改，本人承担审阅与把关职责
- 日常同时维护多个本地仓库
- 已不再将 IDE 作为主力编辑环境，但仍依赖其审阅界面
- 对启动速度与资源占用敏感
- 在本地终端或 AI 工具中完成实际的提交动作

## 4. 使用场景

### 场景一：提交前核对（核心场景）

AI 完成一轮代码修改后，开发者需要确认改动是否符合预期。

1. 唤起 Mini-Git，界面停留在上次审阅的仓库
2. Git 面板的「变更」Tab 展示全部未提交文件
3. 点击第一个文件进入差异对比，用「下一个变更文件」连续推进，逐个检查增删
4. 确认无误后，回到终端或 AI 工具执行提交

**该场景是第一优先级，所有设计取舍以此场景为准。** 场景中的连续推进（FR-6.12）与已查看标记（FR-6.13）是避免漏审的关键环节。

### 场景二：提交后复盘

开发者需要回顾某次已完成提交的具体内容。

1. 在「历史」Tab 的提交列表中定位目标提交
2. 查看提交详情：完整信息、作者、时间、父提交
3. 查看该次提交涉及的文件列表与逐文件差异

### 场景三：历史追溯

开发者需要查找某个功能的引入时间或某处改动的来源。

1. 通过关键词或提交哈希搜索提交历史
2. 按分支过滤，缩小范围
3. 定位到目标提交后查看差异，可顺父提交链继续回溯

### 场景四：项目速览

开发者需要快速了解一个仓库的结构或查看某个文档。

1. 通过文件树浏览目录结构，或用路径模糊查找直达目标文件
2. 打开文件查看内容，Markdown 文件以渲染形式呈现

## 5. 功能需求

### 5.1 仓库管理（首屏）

| 编号 | 需求 | 优先级 | 描述 |
| --- | --- | --- | --- |
| FR-1.1 | 仓库列表 | P0 | 展示已登记的仓库，每项显示仓库名称、完整路径、最近打开时间。按最近打开时间倒序排列，时间相同时按添加顺序排列。「最近打开时间」在成功进入工作台时更新 |
| FR-1.2 | 模糊搜索 | P0 | 顶部搜索框自动聚焦。采用大小写不敏感的子序列匹配，同时匹配仓库名称与完整路径（路径分隔符参与匹配）。排序规则：名称命中优先于路径命中，连续匹配得分高于分散匹配。命中字符高亮，多处可匹配时取最靠左的一组。输入防抖 150 ms。无匹配结果时展示提示 |
| FR-1.3 | 添加仓库 | P0 | 提供「添加仓库」入口，打开系统目录选择器。校验规则见 5.1.2。校验通过则加入列表，失败则就地提示原因（文案见附录 A）且不入列表。校验过程超过 500 ms 时按钮进入加载态，超过 2 秒展示「正在校验…」并提供取消 |
| FR-1.4 | 进入仓库 | P0 | 三种进入方式：双击列表项、选中后按回车、选中后点击底部操作区的「确定」按钮。首屏底部操作区包含「添加仓库」「移除」「确定」三个按钮 |
| FR-1.5 | 键盘导航 | P0 | 上下方向键移动选中项，选中项始终保持在可视区域内。搜索框内按下方向键时焦点移交列表 |
| FR-1.6 | 移除仓库 | P1 | 从列表中移除仓库记录。移除仅删除登记信息与该仓库的会话记录，不触碰磁盘上的任何文件 |
| FR-1.7 | 失效仓库处理 | P1 | 路径不存在或已不是有效仓库的条目不使用禁用样式，而是以警告色左边框与图标标识，行内展示失效原因。悬停露出「重新定位」（打开目录选择器重绑路径，保留最近打开时间与会话记录）与「移除」两个操作。失效检测在首屏渲染后异步执行，不阻塞首屏 |
| FR-1.8 | 启动落点 | P0 | 冷启动时读取持久化的「上次退出时所在界面」，按下表决策。从隐藏态唤起不执行任何恢复逻辑，界面保持原样 |
| FR-1.9 | 首次使用引导 | P1 | 列表为空时展示空状态引导文案与「选择仓库目录」主按钮 |
| FR-1.10 | 返回首屏 | P0 | 工作台的仓库标识区提供返回首屏入口，用于切换仓库 |
| FR-1.11 | 重复添加处理 | P1 | 按规范化路径（解析符号链接 + 大小写折叠）判重。添加已登记仓库时不产生重复条目，仅更新其最近打开时间并选中该条目 |

#### 5.1.1 冷启动落点决策

| 上次退出时所在界面 | 该仓库当前状态 | 落点 | 提示 |
| --- | --- | --- | --- |
| 首屏 | — | 首屏 | 无 |
| 仓库 A 工作台 | 有效 | A 的工作台 | 无 |
| 仓库 A 工作台 | 路径不存在或已非有效仓库 | 首屏，A 在列表中标为失效 | 就地提示失效原因 |
| 仓库 A 工作台 | 已被用户主动移除 | 首屏 | **无任何提示**（移除是用户的显式意图，不应再打扰） |
| 无记录（首次使用） | — | 首屏空状态 | 引导文案 |

#### 5.1.2 有效仓库的判定规则

| 类型 | 判定 | 说明 |
| --- | --- | --- |
| 常规仓库（`.git` 为目录） | 接受 | |
| linked worktree（`.git` 为文件） | 接受 | 需正确解析 `gitdir:` 指向 |
| 子模块工作目录 | 接受 | 作为独立仓库登记 |
| bare 仓库（无工作区） | **首版拒绝** | 提示「该目录是裸仓库，没有工作区，暂不支持」 |
| 选中的是仓库子目录 | 拒绝 | 不向上查找仓库根。提示「该目录不是仓库根目录，请选择包含 .git 的目录」 |
| 选中的是 `.git` 目录本身 | 拒绝 | 提示同上 |
| 路径为符号链接 | 接受 | 登记规范化后的真实路径 |
| 网络驱动器 / UNC 路径 | 接受 | 连接断开时按 FR-1.7 处理 |
| 非 Git 目录 | 拒绝 | 提示「该目录不是 Git 仓库」 |

打开仓库时按精确路径打开，不执行向上遍历父目录的仓库发现行为。

### 5.2 审阅工作台布局

| 编号 | 需求 | 优先级 | 描述 |
| --- | --- | --- | --- |
| FR-2.1 | 三区布局 | P0 | 上半部分为左侧文件树 + 右侧文件查看区，下半部分为 Git 面板。Git 面板内部结构见 5.5 |
| FR-2.2 | 分隔条拖拽 | P0 | 文件树与查看区之间、上半部分与 Git 面板之间可拖拽调整尺寸。最小尺寸：文件树 200 px、查看区 400 px、Git 面板 180 px。拖拽至最小尺寸后继续拖动自动吸附折叠，双击分隔条在「折叠 ↔ 默认尺寸」间切换 |
| FR-2.3 | 面板折叠 | P1 | 文件树与 Git 面板可折叠。折叠后保留 24 px 边缘工具条，含图标与竖排文字标签；Git 面板的工具条额外保留未提交改动数量角标 |
| FR-2.4 | 仓库会话 | P0 | 下列状态构成一个「仓库会话」，按规范化仓库路径分别保存：当前 Tab、文件树展开节点集合、标签页集合与顺序、激活标签页、Git 面板选中项、分隔条位置、面板折叠状态。切换仓库时清空当前视图并加载目标会话，不跨仓库混合标签页。最多保留最近 10 个仓库的会话，超出按最近使用淘汰。持久化级别见 5.8.1 |
| FR-2.5 | 仓库标识 | P0 | 自绘标题栏内常驻展示「仓库名 · 分支名」。游离 HEAD 时展示短哈希并带状态色；仓库处于 MERGING / REBASING / CHERRY-PICKING / BISECTING 状态时展示状态徽标。点击该区域展开仓库切换下拉，其中包含「返回首屏」（FR-1.10） |
| FR-2.6 | 窄窗口降级 | P1 | 窗口宽度 < 1200 px 时，引用树从独立一栏折叠为提交列表顶部的下拉选择器；高度 < 700 px 时，Git 面板默认折叠为底部状态条并保留改动数量角标 |
| FR-2.7 | 切换过渡 | P1 | 进入或切换仓库时立即切到工作台骨架屏，不停留在首屏等待 |

### 5.3 文件树

| 编号 | 需求 | 优先级 | 描述 |
| --- | --- | --- | --- |
| FR-3.1 | 目录浏览 | P0 | 树形展示仓库工作区文件，根节点为仓库根目录。数据源为工作区文件系统，不随提交列表选中项切换到历史版本 |
| FR-3.2 | 懒加载 | P0 | 目录内容在首次展开时才加载，不在进入仓库时扫描整个仓库 |
| FR-3.3 | 排序规则 | P0 | 目录在前、文件在后，各自按固定的自然排序比较函数排列：大小写不敏感、数字按数值大小、前导零不影响数值比较、排序结果不随系统区域设置变化。同名不同大小写时按字节序稳定排序 |
| FR-3.4 | 单击预览 | P0 | 单击文件在查看区打开为预览标签页。预览标签页标题为斜体并带图钉按钮，全局唯一：再次单击其他文件时复用该槽位 |
| FR-3.5 | 预览转固定 | P0 | 以下操作将预览标签页转为常驻标签页：双击文件树项、双击预览标签页本身、点击预览标签页的图钉按钮、在文件树中按回车、双击 Git 面板的变更文件项 |
| FR-3.6 | 文件类型图标 | P1 | 按扩展名展示文件图标，目录展示折叠/展开状态图标。子模块以独立图标标识并标注「子模块」，不可展开 |
| FR-3.7 | 隐藏被忽略项 | P0 | 默认隐藏被忽略的文件与目录。**已被 Git 跟踪的文件即使命中忽略规则也照常展示**（避免用户误以为文件丢失）。忽略判定由后端按整级目录批量返回，不逐文件跨进程请求，且不得通过枚举全仓库忽略集合的方式求取——后者会递归进入被忽略目录内部。忽略规则需覆盖嵌套 `.gitignore`、`.git/info/exclude`、全局忽略文件与否定规则 |
| FR-3.8 | 隐藏 .git | P0 | 不展示 `.git` 目录或 `.git` 文件 |
| FR-3.9 | 变更状态标识 | P1 | 已修改 / 新增 / 删除 / 未跟踪的文件以状态字母与颜色标注，父目录聚合展示后代变更数 |
| FR-3.10 | 节点状态 | P1 | 加载中：超过 200 ms 才展示内联指示器。加载失败：节点下方插入内联错误行与「重试」链接，父节点保持展开，不弹窗。无权限：标注锁图标，展开时内联提示且不报错。空目录：展示「（空目录）」占位 |
| FR-3.11 | 大目录分批渲染 | P1 | 单目录条目超过 1000 条时分批渲染并提示剩余数量 |
| FR-3.12 | 路径模糊查找 | P1 | Ctrl+P 唤起浮层，对仓库已跟踪文件列表做模糊匹配，匹配与高亮算法与 FR-1.2 一致 |
| FR-3.13 | 定位当前文件 | P1 | 标签页栏提供定位按钮与快捷键，展开并滚动到当前文件在树中的位置 |
| FR-3.14 | 符号链接 | P1 | 展示链接目标路径，不跟随解析，不展开 |
| FR-3.15 | 键盘导航 | P1 | 方向键上下移动、左右折叠展开、回车固定打开 |
| FR-3.16 | 上下文菜单 | P1 | 右键提供「复制仓库相对路径」「复制绝对路径」。P2 追加「在文件管理器中显示」 |
| FR-3.17 | 显示被忽略项开关 | P2 | 头部提供开关，开启后以置灰形式展示被忽略项，开关状态按仓库记忆 |

### 5.4 文件查看

| 编号 | 需求 | 优先级 | 描述 |
| --- | --- | --- | --- |
| FR-4.1 | 标签页栏 | P0 | 查看区顶部为标签页栏，超出宽度时横向滚动。标签页可拖拽排序 |
| FR-4.2 | 标签页身份 | P0 | 唯一键 = 文件仓库相对路径 + 内容来源（工作区文件 / 工作区差异 / 提交差异(完整哈希)）。同一文件的内容视图与差异视图是两个独立标签页。标题默认为文件名；差异标签页追加来源标识（`app.ts (工作区)` / `app.ts (a1b2c3d)`）；标题同名时追加最短可区分的父目录。悬停展示完整相对路径与来源 |
| FR-4.3 | 关闭标签页 | P0 | 支持关闭按钮、鼠标中键、Ctrl+W。无标签页时 Ctrl+W 不执行任何操作 |
| FR-4.4 | 代码只读展示 | P0 | 文本文件以只读形式展示，具备行号与语法高亮，内容不可编辑。需阻断的输入通道见 AC-11。首版语法高亮语言清单：JavaScript、TypeScript、JSON、HTML/Vue、CSS、Rust、Python、Go、Java、Shell、Markdown、YAML、TOML、XML、SQL、C/C++。清单外的扩展名以纯文本 + 行号展示，不报错。无扩展名文件按文件名识别（Dockerfile、Makefile、LICENSE 等） |

#### 5.5.6 实现约束

以下约束直接决定 7.1.3 的性能指标能否达成，作为需求的一部分固化：

| 编号 | 约束 |
| --- | --- |
| CN-1 | 提交遍历按时间序进行，禁止使用拓扑排序——拓扑排序需大范围预遍历，在大档仓库上耗时为秒级 |
| CN-2 | 提交列表分页以持久游标增量推进，禁止每页重建遍历器后跳过前 N 条 |
| CN-3 | 提交搜索在独立的仓库句柄与独立线程上执行，不与文件树展开、差异计算共用同一把锁，避免长任务阻塞交互 |
| CN-4 | 全部 Git 读取调用在阻塞线程池中执行，不占用界面事件循环 |
| CN-5 | 引用数量、忽略集合、状态扫描结果按整批返回，不按条目跨进程往返 |

### 5.6 差异对比

> **差异呈现三档模型**（本节全部需求以此为前提）：
>
> | 档位 | 触发条件 | 呈现方式 |
> | --- | --- | --- |
> | 完整档 | 两侧总行数 ≤ 20 000 **且** 两侧内容均 ≤ 2 MiB | 后端返回变更前后完整文本，前端计算行级与行内差异，折叠区域可完整展开 |
> | 退化档 | 超出完整档，但两侧总行数 ≤ 200 000 **且** 两侧内容均 ≤ 20 MiB | 后端返回 unified hunk，仅行级高亮，折叠区域不可展开，界面提示已降级及原因 |
> | 放弃档 | 超出退化档，或任一侧为二进制 | 不计算差异，展示占位提示与变更行数统计（二进制则展示前后文件大小） |

#### 5.8.1 状态持久化级别

| 级别 | 含义 | 适用状态 |
| --- | --- | --- |
| L1 | 仅会话内保持（窗口隐藏 / 显示） | 各区域滚动位置、文件内搜索状态、差异视图的临时视图切换 |
| L2 | 宿主正常退出后恢复 | 仓库列表、上次退出时所在界面、仓库会话（当前 Tab、文件树展开节点、标签页集合与顺序、各标签页的预览/常驻态、激活标签页、Git 面板选中项、历史 Tab 三栏与主分隔条位置、折叠状态、**审阅推进游标、已查看标记集合**）、窗口尺寸与位置、全局快捷键配置 |

L2 状态的写盘时机：变更后防抖 1 秒写入，窗口隐藏时立即写入，宿主退出前立即写入。进程被强制终止时，最后一次防抖窗口内的变更允许丢失。

持久化数据损坏或结构不兼容时降级为默认状态且不崩溃，并在首屏给出一次性提示。

#### 7.3.1 只读禁令清单

下列行为在实现中禁止出现，作为 AC-8.3 静态审计的依据：

| 风险点 | 约束 |
| --- | --- |
| 状态查询的索引更新选项 | 必须显式关闭，禁止在查询工作区状态时回写索引 |
| 差异计算的索引更新选项 | 必须显式关闭 |
| 索引写入 API | 全代码库禁止出现 |
| 仓库发现（向上遍历父目录） | 禁止，必须按精确路径打开 |
| 引用写入、HEAD 设置、检出类 API | 全代码库禁止出现 |
| commit-graph 生成 | 禁止 |

说明：Git 库的 gitattributes / gitignore 缓存为纯内存实现，不落盘，不视为违反只读约束。只读约束意味着不生成 commit-graph、不回写索引 stat 缓存，7.1.3 的性能指标以此为前提。

| NFR-5.5 | Mini-Git 的任何异常不得导致 Open-Toolbox 主进程退出。全部 Git 读取路径不得使用会触发进程终止的错误处理方式，错误一律以可恢复的形式返回并转为 FR-9.4 的用户提示。**约束说明**：宿主 release 配置为 `panic = "abort"`，一次 panic 即终止整个进程，连带关闭便利贴、贴图、计时器等无关窗口。该约束因此无法由运行时兜底，只能靠代码纪律保证，AC-8.3 的静态扫描是其唯一保障手段，属必过项。Mini-Git 解析的是用户机器上任意状态的仓库（损坏对象、浅克隆边界、超大对象），该风险高于其他模块 |
| NFR-5.6 | 配置存储不可写或磁盘已满时，功能降级为纯内存态并给出一次性提示，不崩溃 |

## 9. 发布范围

### 9.1 首个版本包含

全部 P0 与 P1 需求项。

### 9.2 首个版本不包含

- 全部标注为 P2 的需求项
- 2.2.2 节的三项排除项（EX-8、EX-9、EX-10）

### 9.3 后续版本备选方向

以下方向不构成承诺，仅记录可能的演进路径：

- 文件历史：查看单个文件的提交历史与逐版本差异
- 追溯视图：按行展示最后修改该行的提交
- 全文搜索：在仓库内按内容搜索文件
- 提交范围对比：任意两个提交或分支之间的差异
- Mermaid 与更多格式的富渲染
- 暂存与提交能力：若使用中确认需要，再评估是否突破当前的只读定位

## 10. 术语表

| 术语 | 含义 |
| --- | --- |
| 仓库 | 底层 Git 库能成功打开、且具备工作区的本地 Git 版本库。裸仓库不在首版支持范围 |
| 工作区改动 | 尚未提交的文件变更，包含已暂存、未暂存与未跟踪三类。本产品统一以 HEAD 为基准展示，不区分暂存层 |
| 引用 | 分支、标签、HEAD 等指向提交的命名指针 |
| 游离 HEAD | HEAD 直接指向某个提交而非分支的状态 |
| 差异 | 两个版本之间的内容变化 |
| 常驻 | 窗口关闭后不销毁而是隐藏，再次唤起时状态完整保留 |
| 仓库会话 | 一个仓库对应的工作台界面状态集合，定义见 FR-2.4 |
| 预览标签页 | 全局唯一、会被下一次预览操作复用的临时标签页 |
